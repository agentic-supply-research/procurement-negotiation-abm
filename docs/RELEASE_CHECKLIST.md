# Publication and GitHub release checklist

The repository is prepared to be uploaded **later** to a GitHub account. No remote repository, release tag, DOI, or public manuscript link has been created as part of this package.

## Before the first public upload

- [ ] Confirm that the intended GitHub visibility is public.
- [ ] Confirm that the derived GLEE outcome extract can be redistributed under the upstream data terms. If unclear, exclude the 64-row extract from the public release and document how it can be regenerated by authorized users.
- [ ] Review the neutral MIT copyright line and confirm the licensing choice for original code.
- [ ] Check that no personal name, email address, machine path, API key, token, or unpublished manuscript author field was added.
- [ ] Run `python -m unittest discover -s tests -v`, `python tools/verify_outputs.py`, and `python tools/verify_manifest.py`.
- [ ] Check that README and ODD describe the *implemented* behavior rather than claiming live LLM negotiations.

## Suggested repository settings

Recommended neutral repository name: `procurement-negotiation-abm`. Set the repository description to “Negotiation-informed agent-based supply-network simulation and reproducibility materials”. Do not initialize with a different README or license if uploading the contents of this prepared folder.

## After uploading

- [ ] Confirm all expected folders are visible and the GitHub Actions checks pass.
- [ ] Create a version tag (for example, `v1.0.0`) after reviewing the uploaded results.
- [ ] Use a persistent, public GitHub URL in the manuscript’s code/data availability statement.
- [ ] For stronger citation stability, optionally archive the tagged release with a DOI service once ready.
- [ ] Keep the human–LLM versus LLM–LLM calibration distinction explicit in both the article and repository.

No GitHub URL is hard-coded here because the remote repository has not been created.
